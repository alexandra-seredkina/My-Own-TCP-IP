Короче, я разобралась, есть системные вызовы read / write , а есть ioctl - он нужен для управления сетевыми интерфейсами. Через read / write их просто не создать сетевой интерейфс, для этого сделали как раз отдельный ioctl. Есть ещё интерфейс для открытия файла, это не чтение и не запись, это как раз создание File Descriptor, создание потока и присвоение ему номера.

В итоге нам нужно создать поток и получить его номер FD, передать номер FD в ioctl для создания сетевого интерфейса по потоку. И после создания интерфейса по потоку мы сможем в него делать вызовы read / write.

Возвращаясь к TUN/TAP, внеслась по нему ясность, он нужен только для создания НЕ физических сетвых интерфейсов. Это файл ядра и он получает как раз моё сообщение ioctl и создает и возвращает мне интерфейс. Нельзя на любой файл отправить ioctl , работает только с `/dev/net/tun` , потому что это драйвер которые такие сообщения обрабатывает и создает интерфейс уже как раз под капотом.

---

Окей, оказалось ioctl это не чисто с TUN/TAP, это системный вызов что расшифровывается как (_input/output control_)  и его можно использовать с файлами драйверов видеокарт/звуковых карт и.т.д для общения. Он универсальный. Но конкретно с `/dev/net/tun` он работает для создания сетевого интерфейса
